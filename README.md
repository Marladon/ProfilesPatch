# xilab_patch_cfg.py

Скрипт для миграции `.cfg` файлов профилей XILab под новую версию протокола **без запуска GUI**.

## Зачем это нужно

При обновлении протокола libximc в новой версии XILab появляются новые поля настроек. Старые `.cfg` файлы профилей не содержат этих полей — при загрузке XILab молча подставляет дефолтные значения, но при сохранении записывает все поля включая новые.

Раньше процесс "пересохранения" требовал ручной работы через GUI:
1. Запустить XILab
2. Открыть Settings
3. Для каждого файла: Load settings from file → Save settings to file

Этот скрипт делает то же самое напрямую, без GUI.

## Что делает скрипт

1. Читает все `.cfg` файлы в указанной папке
2. Для каждого файла проверяет наличие всех ключей из текущей версии XILab
3. Добавляет отсутствующие ключи с дефолтными значениями (берутся из `motorsettings.cpp` / `stagesettings.cpp`)
4. Сохраняет статус верификации каждого файла:
   - файл был **верифицирован** → хэш пересчитывается, файл остаётся верифицированным
   - файл был **не верифицирован** → хэш не трогается, файл остаётся невалидным

Файлы с актуальными ключами не изменяются.

## Требования

- Python 3.6+
- Стандартная библиотека (никаких зависимостей для установки)

## Использование

```bash
python patch_cfg.py
```

Скрипт автоматически определяет статус верификации каждого файла и действует соответственно.

Если нужно принудительно пересчитать хэш для **всех** файлов (включая намеренно невалидные):

```bash
python patch_cfg.py --rehash
```

Скрипт спросит пути до репозитория XILab и папки с `.cfg` файлами, например:

```
F:\crzy\GITLAB\XILab
F:\crzy\GITLAB\xiresource\profiles\Beijing PDV Instrument
```

## Когда обновлять скрипт

При изменении протокола (тег `protocol updated` в репозитории libximc) достаточно указать путь до обновлённого репозитория — скрипт сам найдёт новые ключи в `motorsettings.cpp` и `stagesettings.cpp`.

## Технические детали

`.cfg` файлы — стандартный INI формат (Qt QSettings). Секция `[VERIFICATION]` содержит дату и MD5 хэш содержимого файла без самой секции `[VERIFICATION]`. Хэш считается от текста в UTF-8 с нормализованными переносами строк (`\n`), точно как это делает XILab через `QFile::Text` + `QCryptographicHash::Md5`.

Статус верификации определяется до внесения изменений: если хэш в `[VERIFICATION]` совпадает с реальным — файл считается верифицированным и хэш пересчитывается после патча. Если не совпадает — хэш остаётся нетронутым.
